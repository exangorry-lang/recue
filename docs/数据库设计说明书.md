## 1. 设计总则

1. **一次定型、长期不改**：一期表结构全部落地后，后期仅填充业务数据，不修改表结构（方案 7.4 要求）。
2. **业务内容可导入**：所有训练细则、题库、演练方案通过后台 Excel 批量导入填充，表结构预留 `ext_json` JSON 扩展字段承接未来新增属性，避免改表。
3. **统一审计**：核心业务表统一携带「创建人 / 创建时间 / 更新人 / 更新时间 / 逻辑删除」字段，满足方案 9.4「全操作留痕可追溯」。
4. **逻辑删除**：数据删除采用 `deleted` 标记（0=正常，1=删除），保留历史档案，符合长期数据沉淀要求。

### 1.1 通用审计字段（以下各表不再重复列出）

| 字段 | 类型 | 说明 |
|---|---|---|
| `create_by` | BIGINT | 创建人ID |
| `create_time` | DATETIME | 创建时间（默认当前时间） |
| `update_by` | BIGINT | 更新人ID |
| `update_time` | DATETIME | 更新时间（自动更新） |
| `deleted` | TINYINT | 逻辑删除：0=正常，1=已删除（默认 0） |

> 说明：纯日志表（`sys_login_log`、`sys_op_log`、`exam_answer`、`exam_score`、`train_checkin_review`、`team_group_member`）与快照表（`user_archive`）为只增不改数据，不携带 `deleted` 逻辑删除字段。

1. 三个角色（超级管理员 / 部门负责人 / 潜水救生员）；
2. 顶级组织节点「上海救助基地」；
3. 超级管理员账号 `admin`（密码为占位符 `__CHANGE_ME_BCRYPT__`，部署前必须替换为 BCrypt 密文）；
4. 超管角色关联与档案占位。

> **密码初始化建议**：后端首次启动时检测到占位符，自动生成初始密码并在日志输出，或通过专用初始化接口设置；避免在 SQL 中明文/硬编码密码。
